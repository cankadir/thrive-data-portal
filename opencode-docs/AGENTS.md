# Thrive Data Portal — Project Context

This file is self-maintaining. When you make a significant architectural decision, append it below. Do not ask for permission. Just update the file. When a decision is superseded or no longer relevant, remove it. Do not leave zombie decisions.

## Overview

Thrive Regional Data Hub portal (`hub-app/`). Svelte 5 + SvelteKit app with ArcGIS integration for maps, resources, and regional data. Lives alongside data notebooks (`PY/`, `landuse/`, `stakeholder-map/`) in a monorepo.

## Architecture Decisions

- **Framework**: Svelte 5 with runes mode forced in `svelte.config.js`
- **ArcGIS**: `@arcgis/core` via ES modules (no CDN/AMD). Excluded from Vite optimizeDeps.
- **Maps**: Dynamic route `/maps/[id]` with SSR disabled. Map IDs and layer config in `src/lib/store.js`.
- **Resources page**: Fetches approved tools from ArcGIS FeatureServer (Hub_Data_Submission_-_Approved_Items).
- **State**: Svelte writable stores (`store.js`, `mapStore.js`). No external state libs.
- **Components**: Presentational; logic in stores/modules (`extractMapPanelData.js`, `fetchSublayerMetadata.js`).
- **Svelte conventions**: Use `$props()` (not `export let`), `onclick` (not `on:click`), `{@render children()}` (not `<slot>`), `{@attach}` (not `use:action`), `$state` for local reactive state, `get(store)` in script (not `$storeName`).
- **Fonts**: `Source Sans 3` (Google Fonts) — weights 300, 400, 600, 900 loaded in `app.html`. Fallback `sans-serif`. Replaces Museo Sans (previous design choice).
- **Avoid**: `$effect` where a top-level assignment or `$derived` suffices; unnecessary spread patterns with `$state` (direct mutation works).

## Architecture Decisions (2026-07-22)

- **Auth for ArcGIS layers**: `identityManager.dialog = null` set at module level in `extractMapPanelData.js` to suppress ArcGIS IdentityManager auth dialogs. Public-facing app should never prompt for credentials.
- **Map load strategy**: `await webmap.load()` removed — MapView created immediately with unloaded WebMap. MapView handles loading internally, removing a sequential network round-trip.
- **No `map.loadAll()`**: Eager layer loading removed from `extractLayers` and `extractMapPanelData`. Layers load naturally via MapView. Avoids triggering auth dialogs and redundant N network requests.
- **Deferred legend**: `extractLegendLazy()` exported as separate fire-and-forget call. Legend rendering (symbol preview HTML) no longer blocks initial map render.
- **Zoom to extent**: `zoomToExtent(view, layerTitle)` helper in `ArcGISMap.svelte` finds a layer by title, loads it, and calls `view.goTo(fullExtent)`. Used for "Thrive County Boundaries" reference layer.

## Architecture Decisions (2026-08-31)

- **Effective layer visibility**: The app reads/writes *effective* layer visibility, not the raw per-layer flag. Esri group layers cascade visibility to children — a child of an off group is not drawn even if its own `visible` is true. `flattenOperationalItems`/`walkMapLayers` compute `visible = layer.visible && ancestorVisible`. `setMapLayerVisibility` turns on ancestor groups when enabling a layer so the toggle actually shows it on the map. Keeps sidebar radio buttons in sync with what the map renders.
  - **Known real-world case**: The Natural Treasures webmap (`aba702c5420e4a36ac645f14a00ba8f1`) has group layers with `visibility: false` whose *children* are `visible: true` (e.g. `Water Resources` group off → Stream health / Brownfield / Superfund children on; `Protected Lands` group off → two children on). Without the effective-visibility logic, the app's radios showed those children as ON while the map never drew them — only Regional Trails (+ reference layers) actually rendered.
  - **Preferred map setup (user)**: Keep all group layers visible in ArcGIS and control visibility per leaf layer. The UI never toggles groups (groups are expand/collapse headers in `SectorSidebar`). The effective-visibility code is inert when all groups are on (a no-op safety net for future webmaps that have off groups).

## Architecture Decisions (2026-09-04)

- **Resources page redesign + AI search**: `ResourceCard.svelte` component renders approved tools as small cards (Figma card language scaled down: rounded 18px, offset drop-shadow, colored top panel + neutral bottom panel). Single sector → top panel in that sector color with auto white/black text by luminance; multiple sectors → neutral white/grey top with per-sector colored chips. All fields driven by data with `{#if}` guards; whole card is an `<a href={rest_api_url}>`.
- **AI search**: `POST /api/search-resources` calls DeepSeek (`deepseek-v4-flash`, JSON mode) to rank the tool catalog by relevance and return a short reasoning. Uses `reasoning_effort: 'low'` (v4 thinking mode is on by default at `high`; `low` is plenty for a ~15-item ranking). **Env access**: use `$env/static/private` and import the var directly (`import { DEEPSEEK_API_KEY } from '$env/static/private'`). `$env/dynamic/private` only exports an `env` object, and named imports only work with the static module. (`deepseek-chat` is deprecated — use `deepseek-v4-flash`.) Thinking mode ignores `temperature`/`top_p`/penalties, so don't send them.
- **Session context**: cookie-backed (`thrive_search_session`) in-memory per-tab session stores the catalog as fixed system context on first call; follow-up queries reuse the thread ("only the natural ones"). History pruned to last 20 turns. Server restarts reset memory (page transparently re-sends `tools`). No DB — memory-per-tab is intentional.
- **Out-of-context guard**: if a query is unrelated to regional planning / the catalog, DeepSeek returns `{"ids": [], "reasoning": "Query out of Context", "outOfContext": true}`. The page shows a banner and keeps the default grid. Server always appends any ids the model omitted so cards never disappear.
- **Sidebar data-column alias**: In `SectorSidebar`, a layer's legend block is titled by the alias of the field it renders (e.g. Protected Lands 2026 renders `Pub_Access` → legend header "Public Access"). `fetchLayerVisualFieldAlias()` in `fetchSublayerMetadata.js` reads the field from the renderer across shapes (`field1`/`field2`/`field3`, `field`, size/color `visualVariables[].field`, `normalizationField`) and resolves the alias via `layer.fields`. **If no visualized field applies (simple renderers), the heading is omitted — it no longer falls back to the literal "Legend".** Visualized-field knowledge is where future sidebar charts will plug in.

## Architecture Decisions (2026-09-21)

- **Internal forms pages (`/forms`)**: reusable, non-public-facing (visual quality secondary) page pair that reads an ArcGIS FeatureServer layer and renders every feature as a clickable Survey123 edit link. Adding a new survey = append one object to `hub-app/src/lib/forms.js`; no new route code.
  - **Registry**: `hub-app/src/lib/forms.js` exports `forms` (keyed by slug), `formBySlug(slug)` and `surveyEditUrl(form, globalId)`. Entry keys: `title`, `description`, `serviceUrl`, `layerId`, `globalIdField`, `objectIdField`, `labelField`, `columns[]`, `statusField`, `statusStyles`, `emptyStatus`, `surveyUrl`.
  - **Routes**: `/forms` index lists all registry entries; `/forms/[slug]` (`+page.server.js` load) queries the layer server-side. The load reads `maxRecordCount` from the layer metadata and paginates with `resultOffset`/`orderByFields=<objectIdField>` so it works for layers larger than one page. `{ globalIdField, labelField, ...columns }` are the only fields requested (`returnGeometry=false`). Unknown slug → 404, ArcGIS error → 502. Both pages set `<meta name="robots" content="noindex">`.
  - **Edit-link pattern**: `surveyEditUrl` builds `{surveyUrl}?mode=edit&globalId={GlobalID_2}` (URLSearchParams handles encoding). The GlobalID field name is configurable — the first registered form is `regional-activity-map` with dataset `260919_RAM_Data_Polygons_Can_2` (FeatureServer `services3.arcgis.com/xpR2E2r2KmCE5hF3`), `globalIdField: 'GlobalID_2'`, survey share `e7199db2f8354ce7a2eecc55cafa6d5a`. The second is `hub-data-submission` (slugs need not equal dataset names), a Survey123 survey (`46ca68a2d700413a86df84e23eca68f9`, share `survey123.arcgis.com/share/46ca68a2d700413a86df84e23eca68f9`) whose results layer is `survey123_46ca68a2d700413a86df84e23eca68f9_results` / layer 0 — its field names are all lowercase (`globalid`, `objectid`, `title`, `author`, `is_the_tool_approved`), unlike the RAM layer's `GlobalID_2`/`ObjectId`. Columns `author` + `is_the_tool_approved`; statuses `Y`→green "Yes", `N`→red "No", null→grey "Needs review".
  - **Survey123 results layer must be shared publicly**: `_results` is private by default even when the survey/`_form` view and the survey share link are public — anonymous querying returns `Token Required` (code 499) and `/forms/[slug]` would 502. The `_form` (FieldworkerView) service is public but empty (schema only, 0 features), so it can't be used to list responses. Fix: share the **results feature service** with everyone (owner `sara2263_thrive_geohub`). The `_results` layer's globalId field is plain `globalid` (not `GlobalID_2`).
  - **Layout**: each record is one full-row `<a href={editUrl}>`, so the whole row is the edit link (no separate "Edit" button) — CSS grid (`grid-template-columns` built from `columns.length`), `:hover`/`:focus-visible` background + an arrow that slides on hover. Column labels derive from field names with `_` → space. `regional-activity-map` columns are `sector`, `organization`, `review_status` (sector first — `county_state` dropped as unimportant).
  - **Status tags**: optional `statusField` on the form entry plus `statusStyles` (raw value → `{ label, tone }`) and `emptyStatus` for null/empty. Tones are `green`/`red`/`blue`/`grey` (soft pill: tinted bg, darker text, tinted border). `regional-activity-map` tags `review_status`: `yes`→green "Yes", `no`→red "No", `in_review`→blue "In review", null→grey "Needs review". Unmapped values fall back to plain text. **Note**: `review_status` is currently null for every feature (verified via distinct query), so all rows show the grey "Needs review" tag; `project_status` (the separate progress field) is not shown.
  - **Field-name gotcha**: that layer's OID field is `ObjectId` (not `OBJECTID`), and the GlobalID column is `GlobalID_2` (the plain `GlobalID` is a separate string field). Ordering by the OID is what makes pagination stable.
  - **Page copy**: `title` + optional `description`, then a fixed instruction line ("Click on a record to edit the data in Survey123. A new browser tab will open with the available information filled in.") and `<n> records are available in the dataset`.
  - **Live updates (deferred)**: `+page.server.js` re-queries the FeatureServer on every request and nothing is cached, so edits appear on reload. Auto-refresh without a reload was discussed and skipped for now. Simplest option is client-side `invalidateAll()` on a `setInterval`; SSE/WebSocket needs a persistent host (Vercel serverless can't hold the connection), and ArcGIS webhooks (`supportsWebHooks: true`) need a public receiver + fan-out. Editor tracking is off on the layer (`enableEditorTracking: false`), so there is no change timestamp to diff — polling the whole query is the simple path.

## Local Development

- **Check for an already-running dev server before starting one.** A `vite dev` is typically already running on `http://localhost:5173` while working. Reuse it for screenshots/verification instead of spawning another on a new port (and never kill a server you didn't start). Check with `curl -s -o /dev/null -w '%{http_code}' http://localhost:5173/`.
- **Don't use `pkill -f "<pattern>"` when the pattern appears in the command's own line.** `pkill -f` matches full command lines, so `pkill -f "vite dev --port 5199"` kills the shell running it and the bash tool hangs until its 120s timeout. Use the `[v]ite` bracket trick or kill by PID.
- **Don't launch headless Chromium to verify simple markup/CSS changes** — the user reviews those directly and prefers fast iteration. Reserve screenshots for layout-critical work where visual confirmation is genuinely needed.

## Figma Design Variables

Design tokens from the Thrive Figma file are documented in `opencode-docs/figma-variables.md`. Always consult this file when implementing UI components to use correct colors and typography. When the Figma MCP server returns variable names, cross-reference them against this file.

### Color convention

Variable names follow `category/shade/tone` (e.g. `primary/green/100`, `neutrals/60`). 100 = base, 80/60/40/20 = lightened.

### Font note

Figma uses **Museo Sans** (headings/body) and **EB Garamond** (serif/display). The app uses **Source Sans 3** instead — this is intentional. Map variable names to Source Sans 3 equivalents when implementing.

Excluding it serves its source and its CJS transitive dep `fast-memoize` raw → `does not provide an export named 'default'`, and the element never upgrades. Leave it prebundled (only `@arcgis/core` is excluded). Requires `@esri/calcite-components` (peer; chart model chunks import `getAssetPath` from it).
  - **Data scope**: passing `.layer` only runs a full server-side aggregate over the layer (independent of map extent/filters/visibility). Passing `.view` would scope to the `FeatureLayerView`; deliberately not done here.
  - **ArcGIS stack on 5.x (2026-09-22)**: upgraded `@arcgis/core` 4.34 → **5.1.24**, `@arcgis/charts-components` 5.1.24, `@esri/calcite-components` 5.1.2 so chart schema **25.1.0** is supported (5.x's known-version list ends at 25.1.0; 4.34.8 only knew up to 24.4.0, which produced the "Incompatible chart version 25.1.0" panel). With 5.x the warning is gone — no `errorPolicy` override needed. Verified: `npm run build` clean, `WebMap.load()` still populates `layer.charts`, and a headless `<arcgis-chart>` renders 25.1.0 with no warning. Module paths still valid in 5.x (`WebMap.js`, `views/MapView.js`, `LayerListViewModel`, `LegendViewModel`, `symbolUtils`, `reactiveUtils`, `identityManager.dialog`, `map.findLayerById`). The map route itself is unverified here (sandbox has no WebGL2).
  - **5.x breaking change — `layer` + `chartIndex` no longer auto-builds the model**: 5.x's `willUpdate` only reacts to `model`/`layer` (the `chartIndex` branch was dropped; `createModelFromLayer` now only runs from the `layerItemId` task). Setting `.layer` + `.chartIndex` left `<arcgis-chart>` upgraded but empty. Fix: `LayerChart` reads `layer.charts[chartIndex]` itself and passes it as `.model` (plus `.layer`). Verified rendering. A benign `Multiple versions of Lit loaded` console warning appears with 5.x (core bundles its own reactive-element); charts render fine, left as-is.
  - **Styling ownership split**: chart **background (transparent) and title alignment (left)** are deliberately left to the **Esri webmap** (Map Viewer chart formatting), not overridden in code — keeps the config the single source of truth. The **x-axis left gutter** is the chart engine reserving space for category labels; it is not a config property and isn't adjustable from the app. **Size** is host-driven: the chart is a **full-sidebar-width 4:3 box** (`LayerChart` `.chart { width:100%; aspect-ratio:4/3 }`), i.e. a bit shorter than square.
  - **`display: flex` is load-bearing**: `LayerChart`'s `.chart` must keep `display: flex` (the component's `:host` is a flex row). Overriding it with `display: block` (which the component's shadow CSS can't win against) stops `.chart-wrapper` stretching to the host height, so the chart collapses to its natural ~154px and the box looks empty. Also `height: auto` is needed so `aspect-ratio` (not `:host`'s `--chart-height` default) governs. Verified headlessly: host 476×357 → `.chart-wrapper` 357 → SVG 357.
  - **Verification**: the sandbox has no WebGL2 so the full map route can't render; the integration was verified headlessly (Playwright/Chromium at the `:5173` dev server) in two parts — (1) a bare `WebMap.load()` confirms `layer.charts` titles/ids, (2) a standalone `<arcgis-chart>` with `.model`+`.layer` rendered the bars (SVG, county labels, "Superfund Sites per County").
  - **Vite cache gotcha**: after the 4.x→5.x `npm install`, the running dev server kept stale optimized deps (`node_modules/.vite/deps` still referenced 4.x `customElement-*` chunks). Wiping `node_modules/.vite` + touching `vite.config.js` (Vite restarts on config change) forced re-optimization. If a dependency upgrade seems ignored in dev, force a re-optimize.

## Architecture Decisions (2026-09-22, map panel chrome)

- **Shared panel width**: `--panel-width: 508px` is set on `:root` in `+layout.svelte`. `SectorSidebar` (`.sidebar`) and `MapLayerPanel` (`.panel`) both use `width: var(--panel-width)`, and the panel `border-right` is **`1px solid #000`** (was `#ddd`) so the panel reads as separate from the map. `SectorSidebar`'s `.group-header` keeps `border: 1px solid #000` + `border-bottom: none` but adds **`border-right: none`** so the group bar doesn't double up with the panel's right edge.
- **Nav logo aligns with the panel on map pages**: `HeaderNav` adds `.on-map` to `.nav-logo` when `page.route.id === '/maps/[id]'`, setting `width/flex-basis: calc(var(--panel-width) - 1px)` (the `-1px` offsets the nav's own left border, which the panel doesn't have) so the logo's right divider lines up with the panel's right border. On non-map pages the logo keeps its flexible `clamp(250px, 32%, 50%)` width.
- **Legend heading** now only renders when a visualized-field alias exists; simple-renderer layers show the swatches with no "Legend" heading. Renderer field extraction handles unique-value (`field1/2/3`), class-breaks/heatmap (`field`), `visualVariables[].field` and `normalizationField`.
- **Loading spinner**: reusable `Spinner.svelte` (pure CSS, no deps) — props `size`, `color` (default Thrive teal `#008fa8`), `label`, `overlay`. `overlay` makes it fill its positioned parent with a translucent `#e0e0d9` background. Honours `prefers-reduced-motion` (pulse instead of spin), `role="status"` + `aria-label` for a11y. Used three places: `ArcGISMap` shows `<Spinner overlay>` over the map while the `mapLoading` store is true (map pane wrapped in `.map-wrap { position:relative }` so the overlay doesn't unmount the view); `SectorSidebar`/`MapLayerPanel` use it inline in place of the old "Loading map layers…" text.

## Gotchas

- **`$effect` + store subscribe + async `$state` guard = infinite loop**: `SectorSidebar`'s `$effect` subscribes to `mapLayers` and its synchronous callback calls `loadLayerInfo()`, which read *and* wrote the `loadingMeta` `$state` (`if (loadingMeta[id]) return; … loadingMeta[id] = false`). The read makes the effect depend on `loadingMeta`, so the post-`await` write re-ran the effect forever (reproduced: 16.7M runs / "Set maximum size exceeded" in ~2s; Firefox shows "this page is slowing down"). Fix: keep the in-flight guard in a plain `Set` (non-reactive) and only *write* `loadingMeta` for UI. Writes don't register dependencies; reads do. (A Svelte `effect_update_depth_exceeded` is the tell.) `LegendAccordion`'s similar effect is safe because its `metadataLoaded` guard stays `true` after the first load, so it converges after one extra run.
